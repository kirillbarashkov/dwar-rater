# Dwar Rater — описание и цели проекта

## Одной строкой

**Dwar Rater** — веб-приложение для клана в игре «Легенда: Наследие Драконов» (dwar.ru):
берёт открытые данные с сайта игры и превращает их в инструменты для игрока, казначея
и руководства клана.

## Зачем он нужен

До проекта всё считалось руками: таблицы налога, сверка состава, «кто что сдал»,
«кто остался должен», история уровней и улучшений жили в чужих головах и разрозненных
файлах. Из этого следуют пять целей, которые проект закрывает:

1. **Убрать ручной труд.** Импорт казны и состава прямо с сайта игры, налоги и сдача
   ресурсов считаются сами, отчёты строятся по кнопке.
2. **Сделать казну прозрачной.** Видно, кто сколько сдал, кто должен, что учтено, какая
   переплата перенесена. Спорные случаи не исчезают из отчётов, а показываются отдельно.
3. **Хранить историю.** Слепки персонажей, история казны по месяцам, события состава,
   переносы переплаты, уровни клана — с возможностью вернуться назад.
4. **Давать инструмент прогресса.** Трек улучшений: что купить, что даст больше всего
   пользы за потраченное, какие шаги уже закрыты.
5. **Не терять данные.** Бэкапы, аудит действий, журнал корректировок с откатом,
   закрытие месяца, диагностика порченых записей.

## Для кого

| Кто | Что получает |
|---|---|
| **Игрок** | Разбор своего персонажа по ссылке: характеристики, экипировка, эффекты, медали; история слепков и трек улучшений |
| **Казначей** | Импорт казны, журнал операций, аналитика налогов, обмены и долги, «Статус персонажа», группы исключений, закрытие месяца |
| **Глава и совет** | Состав клана с ролями и историей, диагностика расхождений, чат, уровни клана |

## Ключевые возможности

### Персонаж и анализ

- Разбор персонажа по ссылке: характеристики, экипировка и сеты, временные и постоянные
  эффекты, медали с расчётом репутаций, рекорды, профессии.
- Категоризация эффектов (баффы, эликсиры, маунты, дебаффы) и расчёт репутации по медалям.
- Кэш анализа: повторный разбор не дёргает сайт игры без необходимости.
- **Закрытые профили**: мониторинг — открылся ли профиль, который был закрыт.

### Слепки, сравнение, сценарии

- **Слепки**: сохранение результата анализа в базу, история и загрузка нужного слепка.
  Для закрытого профиля слепки остаются единственным источником данных — вкладка
  показывает их прямо в карточке персонажа.
- **Сравнение**: несколько персонажей рядом, плюс личный список «Мой список».
- **Сценарии прокачки**: целевые ориентиры и сравнение персонажа со сценарием.

### Трек улучшений

- Движок «закрытия разрывов»: узкие места, фазы, ROI и авто-пересчёт при повторном анализе.
- Трек живёт отдельно от анализа персонажа: открывается сам, помнит источник и умеет
  показывать пустое состояние с подсказкой «что делать дальше».

### Клан

- Информация о клане: уровень, история уровневых событий, вложения.
- **Состав**: импорт с сайта игры, роли (глава, совет, заместители, набор), пробные
  метки, история и события состава, выбывшие, флаги расхождений.
- Единое правило роли: «главная роль» выбирается в интерфейсе и выигрывает у роли из
  импорта; единственный глава — инвариант, который держит импорт.
- Чат клана: комнаты и сообщения.

### Казначейство

- **Импорт казны** за период с сайта игры: оценка объёма, устойчивость к обрывам,
  идемпотентный повторный импорт, журнал операций, экспорт и бэкапы казны.
- **Аналитика налогов**: сдано, учтено, переплата, сдача ресурсов по группам, полоса
  покрытия периода, сверка с составом.
- **Налоговый контур**: движок налога, порог сверхнормы, автоперенос переплаты
  (роль «Казначей» — отдельные права), массовый зачёт с предпросмотром «что изменится».
- **Обмены и долги**: операции, которыми ресурс меняли на ресурс, деньги на ресурсы,
  или брали в долг, — сводятся в **пары**. Автоматика предлагает кандидатов, казначей
  подтверждает; подтверждённая пара видна явно, корректируется через отдельное окно,
  каждое изменение пишется в лог. Пару можно разорвать, а разрыв списывается на таланты
  клана.
- **Статус персонажа**: состояние дел участника за месяц — налог, переплата, учтено,
  ресурсы, открытые долги, обмены «что на что» — и история по месяцам.
- **Группы исключений**: правила по названию ресурса, которые убирают операции из отчётов
  совсем или переводят их в нейтральные.
- **Займы из казны**: отдельная вкладка — кто брал из казны и не вернул.
- **Порядок и надёжность**: закрытие месяца (заморозка и переоткрытие с причиной),
  диагностика порченых записей с подавлением принятых находок, перенос истории при
  переименовании персонажа, аудит импорта состава.
- **Термины**: казначейские понятия («учтено», «переплата», «сверхнорма») объясняются
  в интерфейсе подсказками, а не только в голове казначея.

### Администрирование

- **Роли и права (RBAC)**: матрица «фича × действие» с уровнями full / read / none,
  персональные исключения на пользователя, шесть ролей (admin, superuser, user, custom,
  treasurer).
- Управление пользователями, синхронизация из состава клана, привязка персонажа.
- **Бэкапы БД**: создание, скачивание, восстановление, удаление; ежедневный автобэкап.
- **Audit Log**: журнал действий с фильтрами.
- **Swagger** прямо в админке — живая спецификация API (`/api/openapi.yaml`).

### Общее

- Сессионная авторизация (Bearer), TOTP 2FA для администраторов, одна активная сессия
  на пользователя, ограничение частоты запросов.
- Светлая и тёмная темы.
- Экспорт данных персонажа.
- **Раздел «О проекте»** — тот, что вы сейчас читаете: цели и ключевые возможности, лента
  важных изменений, полный архив релизов и реестр техдолга. Тексты живут в репозитории и
  приезжают вместе с релизом, поэтому описание не может разойтись с кодом.

## Как устроено

| Слой | Технологии |
|---|---|
| Фронтенд | React 19 + TypeScript + Vite |
| Бэкенд | Python + Flask (Blueprint-фичи), SQLAlchemy 2.0 |
| База | PostgreSQL 16, миграции — Alembic (forward-only) |
| Поставка | Docker Compose, nginx перед фронтом, прод на Cloud.ru |
| CI/CD | GitHub Actions: тесты → сборка → деплой → проверка здоровья |
| Версии | `VERSION` — эталон, теги ставит CI, `RELEASE_NOTES.md` собирается из истории git |

Каждая фича — вертикальный срез: маршрут, сервис, модель, тесты и клиент фронта рядом.
Контракт API описан в OpenAPI и сверяется с кодом автоматически.

## Что считается «готовым»

Изменение не считается сделанным, пока не пройден цикл: тесты бэкенда, `tsc -b`, линтер
фронта, смоук на dev-стенде, затем деплой и проверка прода по версии и здоровью. Уровень
релиза (patch / minor / major) согласуется с владельцем проекта **до** выкладки.

## Границы: чего приложение не делает

- **Один клан.** Идентификатор клана зашит (`/clan/2315`); мультиклановость не планируется.
- **Ник как ключ.** История операций и уровней привязана к нику, а не к идентификатору
  персонажа, поэтому переименование лечится отдельным инструментом переноса (TD-5).
- **Источник — сайт игры.** Разбор опирается на разметку dwar.ru: если она меняется,
  правится парсер (это регулярная, а не разовая работа).
- **Не публичный сервис.** Всё закрыто авторизацией; сторонних пользователей и открытой
  регистрации нет.

Подробности по каждому релизу — в соседних табах. Открытые долги и согласованные,
но не начатые планы — в табе «Техдолг».
